Skill Verify

Usage guide

This guide is the search entry point for the repository. It covers local use, CI use, rule interpretation, generated files, and the limit of a static pass.

Run locally

No installation is required from a clone:

python3 scripts/skill_verify.py path/to/skill
python3 scripts/skill_verify.py skills/ --recursive
python3 scripts/skill_verify.py skills/ --recursive --format json
python3 scripts/skill_verify.py path/to/skill --format sarif --output results.sarif

Python 3.8 or newer is supported. The package has no runtime dependencies.

Rule groups

Structure and references

The structure and reference rules are SV000, SV001–SV006, SV010, and SV012. They cover an unreadable file, frontmatter, names, descriptions, missing local paths, and path escape. A broken reference is an error because the file a skill claims to ship is absent.

Instruction risk

SV020 through SV027 cover instruction override, prompt or credential disclosure, credential exfiltration, remote shell pipelines, unbounded deletion, attempts to hide behavior from the user, invisible Unicode, and instruction-like HTML comments.

Generated and runtime files

A skill may legitimately read a file that is created later, such as full_text.txt. Declare the exception explicitly instead of disabling SV010 globally:

python3 scripts/skill_verify.py path/to/skill \
  --allow-missing full_text.txt \
  --allow-missing 'outputs/*.json'

The exemption applies only to missing paths. A reference that escapes the skill directory is still SV012.

GitHub Actions

name: Verify skills
on: [push, pull_request]
jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: wu350891451-jpg/skill-verify@v0.1.1
        with:
          path: skills
          recursive: "true"

The action exposes result, errors, warnings, failed-skills, and scanned-skills outputs.

SARIF and code scanning

- uses: wu350891451-jpg/skill-verify@v0.1.1
  with:
    path: skills
    recursive: "true"
    format: sarif
    output: skill-verify.sarif
- uses: github/codeql-action/upload-sarif@v3
  with:
    sarif_file: skill-verify.sarif

What a pass does not mean

A pass is not a sandbox result, a provenance signature, a malware verdict, or proof that a skill is harmless. The rules are narrow by design and a malicious author can evade every string pattern.
